Phase 0 · design only

Unified Inbox AI Service

One place for a user's mail, calendar and chats, sorted by channel and topic, summarised, and searchable through an assistant that drafts replies but never sends without a click.

DecisionsArchitectureChannelsLLM gatewaySecurityRisksPhases

What is decided

  • BackendNestJS (TypeScript), modular monolith
  • DataPostgreSQL + pgvector with row-level security; Redis + BullMQ
  • Web clientVite + React + TypeScript
  • App loginEmail, Google and Microsoft from day one
  • LLM providersAnthropic first, then Gemini, OpenAI, Grok
  • EmbeddingsHosted model through the gateway, no local model
  • ScaleUnder 1,000 users; individuals and small orgs
  • InfrastructureDocker Compose only; cloud chosen in Phase 6

Architecture

Seven modules share one deployable: Auth, Connectors, Ingestion, AI, Chat, Notifications and Admin. Each owns its tables and talks to the others through service interfaces, so any of them can be split out later.

Replies are never automatic

The assistant stores a draft. Only an authenticated "send" call on that draft reaches the connector, and every send is written to the audit log.

LLM gateway

Business code asks for a task such as summarize, never a vendor. The admin maps each task to a provider and model, with retries, a fallback route, quotas, redaction of emails, phone numbers and IDs before prompts, and a per-channel "AI off" switch. Prompt templates are versioned in the database.

Security and privacy

  • Row-level security in Postgres, set per request, so one user cannot read another's rows even if application code is wrong.
  • OAuth tokens and provider keys use envelope encryption and never appear in logs.
  • Every webhook signature is verified before parsing (Slack, Microsoft Graph, Meta, Google Pub/Sub).
  • Consent, export and hard delete support Malaysia PDPA and GDPR. A legal review is advised before launch.
  • A tenant-isolation test suite runs in CI, including a vector-search leakage test.
